## Reproducing it

```bash
# terminal 1
ros2 launch sim_bridge2 go2_sim.launch.py

# terminal 2
ros2 launch smartfarm_inspector smartfarm.launch.py auto_launch:=false

# terminal 3
ros2 topic pub --once /farm/inspection_request std_msgs/msg/String \
  "data: 'check the north field for powdery mildew on tomatoes'"

ros2 action send_goal /mission/launch \
  navigation_interfaces/action/LaunchCurrentMission '{request: {}}'
```

## Generalisation beyond a single prompt

The rules recommend showing a second mission phrased differently. Seven varied
requests were run live against the model; all seven were first-pass valid with
no repair rounds. Full results in `05_kpi/KPI_Report.xlsx`.

The most informative is the one that was **refused**:

```
Request: "inspect the west orchard"
Result : CLARIFICATION_NEEDED — nothing published, robot did not move
Message: "'West orchard' is not a field on Demo Farm North.
          Did you mean north_field, central_field, or south_field?"
```

The model could have guessed `north_field` from the word "west" and sent the
robot to the wrong field. It declined instead. That message was generated by
the model, grounded in the actual farm listing — not a hardcoded fallback.

A second refusal shows the deterministic validator catching what the LLM was
willing to propose:

```
Request: "check everything"
Parsed : all three fields (confidence 0.60)
Task   : 39 waypoints, 300.6 m, 105.2 Wh — 97% of usable energy
Result : REJECTED, ENERGY_MARGIN — mission not published
```

## Known issues visible in the recording

- **Parked vehicles are visible in the field.** The test world reuses the
  simulator's default obstacle layout with crop plants added. The rows
  themselves are clear and every waypoint was reachable.
- The mission runs at 0.3 m/s inspection speed, so the walk is slow. The
  recording is uncut to show one complete mission end to end.
